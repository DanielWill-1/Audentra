For form users

From template to saved form

  1. 01

    Choose or create a template

    A template defines the prompts and input types for the form. Create one in Templates, or open an existing one.

  2. 02

    Fill the form

    Use typed answers or the voice assistant. You can choose a template first, or open AI Voice Auto-Fill and select one.

  3. 03

    Review every value

    Suggestions update a draft. Correct the visible fields yourself and submit only when they are ready.

  4. 04

    Save, then reopen the record

    Choose Save filled form. Find the record in Saved forms or the dashboard’s five most recent items.

The voice conversation is not a saved form. The record is created only when you review the form and save it.

Voice workflow

Record, transcribe, review

On AI Voice Auto-Fill, select a template and either type an answer or select Record. The browser asks for microphone access when recording starts. You may stop, listen, and transcribe the clip before sending, or send the recording with your message.

  1. 1Provide an answer. Use typed text if you do not want to record, or record a short response.
  2. 2Check the transcript and suggestions. The assistant can ask a follow-up and propose values for matching fields. Invalid values can be rejected.
  3. 3Review the form itself. Required fields and field types are checked when you submit. You can edit every displayed value before saving.
  4. 4Save the completed form. A successful save opens its record in Saved forms.

If microphone access or a provider request fails, the page shows an error. You can still type answers and review the form. See Voice and data use before sending information for cloud processing.

Template format

Define fields in form_data.fields

Templates store a list of field definitions. Each field has an id and a type; labels, required markers, and type-specific options describe the form. The application uses these definitions directly. It does not run a JSON Schema compiler.

Example form_data.fields · JSON
{
  "fields": [
    {
      "id": "full_name",
      "label": "Full name",
      "type": "text",
      "required": true
    },
    {
      "id": "email",
      "label": "Email",
      "type": "email",
      "required": true
    },
    {
      "id": "contact_method",
      "label": "Preferred contact method",
      "type": "select",
      "required": true,
      "options": ["Email", "Phone"]
    },
    {
      "id": "age",
      "label": "Age",
      "type": "number",
      "required": false,
      "min": 0,
      "max": 120
    }
  ]
}

Supported field types

text, email, number, date, select, radio, and checkbox.

Field-specific rules

Use options for select/radio fields, min/max for numbers, and minLength/maxLength for text. Required values are checked on form submission.

Build a form with the visual editor on Templates, or export a template JSON file there. Keep field IDs stable: voice suggestions are matched to the field ID or label.

Saved records

Recent Forms and Saved forms

The dashboard shows the five most recently saved form records. Select View to open that exact record. The Saved forms page shows account-owned records in pages, lets you inspect a record, download its JSON, or delete it. Deletion requires confirmation and removes the saved record.

Saved forms are completed records

The voice form’s conversation and unsaved field draft are not listed here. This release does not save or resume unfinished drafts.

Download the data you need

Use Download JSON on a record to get its stored field values and template reference.

Personal history

Use the Activity Log

The Activity Log records saved actions in five categories: Forms, Templates, Sharing, Reviews, and Schedules. Search by text, choose a category, and select a date range. Matching entries can be paged through. Links open a related record only while your account still has access.

Removing history is different from deleting a record. “Remove from activity” removes that history entry. It does not delete its saved form, template, share, review, or schedule.

Workspace guides

Sharing, reviews, and schedules

These features use the existing template and scheduler pages. They do not create external invitation links or deliver reminder messages.

Share a template or review it

  1. Open Templates → Collaboration and reviews.
  2. To share, enter recipient UUIDs for existing accounts and choose a role. No invitation email or anonymous share link is created.
  3. Request a review or submit a rating and comment for the owner. Reviewers can update their own review; the owner can process items in the review queue.

Create and manage a schedule

Use Scheduler to create a form review, team meeting, training, maintenance, or other event. You can edit, complete, cancel, or delete an event and filter the calendar. Reminder minutes are stored as schedule metadata; reminder delivery is not active.

Scheduler Settings

Preview preferences in your browser

The protected Scheduler Settings page controls a fictional sample event and calendar. Duration, reminder offset, working hours/days, calendar view, week start, weekends, and compact display update that example only. They do not change actual events or availability rules.

  • Changes stay in a draft until you save. Discard restores the last saved version; Reset puts defaults in the draft.
  • Preferences are stored in this browser profile on this device. They are not synchronized between devices or used as server scheduling settings.
  • Import accepts supported preferences from the current version and older browser exports; export contains preferences only, with no account identifier.
  • Calendar connections and reminder delivery are unavailable. The page does not request calendar or notification permissions.

Voice and data use

Know what is sent for processing

Microphone access starts only after you choose to record. If a real cloud provider is selected and configured, VoiceForm asks for consent before its first cloud AI request. Depending on the action, the app can send a recording for transcription, typed message and recent conversation with field definitions and current draft values for extraction, or reply text for speech synthesis. The current consent notice names Groq Whisper, GPT-OSS, and Orpheus for these configured paths. Mock mode uses local mock adapters and is not evidence that a live provider handled a request.

The consent notice explains that the app owner has Zero Data Retention disabled for the Groq organization and that Groq may log inference inputs and outputs for reliability or abuse investigations for up to 30 days, plus usage metadata. Provider configuration can vary between deployments. Review the current Privacy Notice and Security page before sending sensitive information.

Transcription upload limits are configured by the server and may also be constrained by the browser or hosting layer. The Django development default is 20 MiB for the request and audio limit; the effective limit may be lower elsewhere. Do not treat a client-side limit as a guarantee for another deployment.

For developers

Start the current app locally

On Windows, install PowerShell, uv, the Supabase CLI, and Docker Desktop. Start Docker Desktop, open PowerShell at the repository root, and run:

PowerShell · repository root
powershell -NoProfile -ExecutionPolicy Bypass -File .\start-local.ps1

The launcher prepares the locked Python environment, starts local Supabase, applies forward migrations without a reset, builds static CSS, checks Django, and starts Waitress. Then open http://127.0.0.1:8000/. Stop the foreground server with Ctrl+C.

Use -Port 8001 when you need a different local port. First setup may download the managed Python, dependencies, and pinned Tailwind executable. The repository README and docs/deployment/P10_LOCAL_RUNBOOK.md contain recovery and manual setup details.

Active stack

Python 3.12, Django 5.2, server-rendered Django templates, HTMX, JavaScript, and Tailwind CSS. Waitress serves the WSGI app and WhiteNoise serves static files. Supabase provides local Auth and PostgreSQL for the one-command development setup.

Legacy application

The former React, Vite, Express, and Node workflow is archived under legacy/. It is retained for source reference and is not used by the current Django launcher or runtime.

Developer reference

Internal HTTP routes

These are internal routes used by the application, not a supported public SDK. Requests are POST-only and require the verified VoiceForm session, the normal Django CSRF token, the configured private-service boundary, and an enabled service. Cloud consent is required when the selected speech or AI provider is real rather than mock.

Internal speech and AI HTTP endpoints
RouteRequest bodySuccessful response
POST /api/transcribe/multipart/form-data: audio file and mimeType.JSON object with transcript.
POST /api/tts/JSON object with text; optional voice and options.JSON object with base64 audioContent and metadata.
POST /api/ai/extract/JSON object with userInput, formFields, currentFormData, and conversation.JSON object with assistant response and validated extractedData.

Errors are JSON objects with an error message. Depending on the failure, responses can report missing authentication, CSRF or private-boundary rejection, disabled service, invalid content, request size, rate limit, missing consent, or provider failure. Limits and provider availability come from the server configuration.
