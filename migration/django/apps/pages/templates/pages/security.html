Current application controls

Security

This page describes controls implemented in the current Django application. Provider accounts, hosting, network configuration, and operational processes also affect the security of a live deployment.

Verified account access

Protected Django routes require a server-verified Supabase identity. Database operations run in a transaction with that user’s PostgreSQL row-level security context.

Request boundaries

Service endpoints check the private request boundary, CSRF rules and allowed origins, limit request sizes, apply a per-process rate limit, and require the current cloud-consent policy version before live provider requests.

Server-side provider credentials

Groq requests are made from the backend over HTTPS. Provider credentials are read by the server and are not part of the browser request payload.

Session and log handling

The Django runtime stores sessions server-side. Its production settings use secure cookies and HTTPS redirection. Application logs are reduced to fixed event labels without request contents.

Database and file access

The development Supabase schema has owner-scoped row-level policies for saved forms and private file storage. The reviewed development project passed the repository’s P5/P9 schema and storage acceptance checks. That evidence does not certify a separate production deployment or its operator configuration.

Cloud processing

The current AI path sends audio, form fields, draft values, and conversation text to Groq after the user opts in. The browser communicates with the VoiceForm server first; Django rejects live-provider requests without the current consent policy version. The app owner confirms Zero Data Retention is disabled for this Groq organization. See the Privacy Notice for retention details.

Claims not made

VoiceForm does not claim end-to-end encryption, a specific at-rest encryption scheme, blockchain verification, a 99.99% uptime commitment, HIPAA/HITECH compliance, GDPR/CCPA compliance, SOC 2, or ISO 27001 certification.

Reporting a security concern

Contact the project through the Contact page. Do not include user data or credentials in a report. No response-time commitment is stated here.
