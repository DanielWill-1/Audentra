# P6 implementation report

**Review addendum, 2026-10-11:** The isolated suite was rerun (115 passed), and the Django system check remained clean. [P6_REVIEW.md](P6_REVIEW.md) records two open medium findings: ordinary tests depend on ignored compiled artifacts, and malformed upstream redirects escape sanitized error handling. Both are assigned before W1 cutover in root [prompt.md](../../prompt.md). The implementation results below remain historical evidence; P7 has not started.

P6 adds reusable Django public and application shells, accessible shared fragments, local shell behavior and a disabled-by-default legacy page bridge. The route bridge forwards only the 21 reviewed public/application routes in the locked P1 manifest. The four React authentication routes remain excluded; `/reset-password` stays a local 404 until its Django recovery flow is implemented. Product page bodies remain for P7.

The page and asset bridge uses a fixed configured origin, requires raw request-target validation, forwards only GET/HEAD, strips credentials and untrusted forwarding headers, bounds timeouts and response sizes, verifies exact content hashes, blocks unsafe redirects and self-target loops, and returns sanitized errors. Assets have a separate four-file allowlist. Manifest drift now disables every fallback route until ownership is reviewed again. The bridge is off by default; plain HTTP is accepted only for a loopback origin while `DEBUG` is true.

The public/app templates share base document and accessibility fragments while keeping separate layouts. Local Lucide SVG symbols, pinned Tailwind tokens, an idempotent dialog/drawer controller and responsive fixtures are included. `/__p6/public` and `/__p6/app` are synthetic preview routes gated by DEBUG, loopback host and an explicit setting. The existing Auth pages and services retain their route ownership and HTMX behavior.

Verification passed: 115 isolated tests, Django system check, focused Ruff and mypy, pinned Tailwind build/token checks, static collection, and Playwright checks at desktop and mobile widths. Browser evidence includes both shell fixtures, the actual preserved Vite homepage delivered through Django, and a synthetic P4 HTMX validation swap. See [P6_VERIFICATION.md](P6_VERIFICATION.md), [P6_ROUTE_OWNERSHIP.json](P6_ROUTE_OWNERSHIP.json), [P6_ASSET_INVENTORY.md](P6_ASSET_INVENTORY.md) and [P6_ROLLBACK.md](P6_ROLLBACK.md).

The working bundle was copied into ignored project-local scratch storage and the original `dist/client` was preserved. The exact document/assets passed digest checks and were loaded in Chromium. Rebuild and refresh their inventory during P7 to prove the current source bundle.

P6 did not migrate page bodies, access the hosted database/Auth/Storage services, call speech providers, expose credentials, or create accounts. P1 accepted reference exceptions, P3 live provider/device evidence and P4 recovery/production/security follow-ups remain documented.
